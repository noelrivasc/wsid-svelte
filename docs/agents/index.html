Agent notes

Guidance for AI agents working in this repo. Read this before creating or moving files.

Before touching files

  • Read code layout & conventions. Each kind of code has a single predictable home — schemas in schemas/, persistence in store/, pure logic in engine/, presentational code in components/, glue in routes/.
  • Before creating a file or directory, verify the target path against those conventions. If the user-supplied path doesn't match, propose the correct path and confirm before proceeding.
  • Read styling before adding any UI. The project overrides Tailwind's default red/blue scales; only the documented tokens resolve.

Configuration access

Never read process.env or $env/* directly. Use $lib/utils/config from SvelteKit server code, or $lib/utils/config.runtime from CLI / tsx scripts. See env.

Database access

Routes and components never touch store/db or write SQL. Go through a repository (store/entityRepository.ts) and call named functions. New entity? Add a new repository file.

Schemas first

If a domain shape needs to change, edit the Zod schema in src/lib/schemas/ first. The store, engine, and components consume the inferred types — keeping the schema as the single source of truth prevents drift.

Pure engine

Anything in src/lib/engine/ must remain pure: no Date.now(), no Math.random(), no IO. IDs and timestamps are passed in from the caller. This is what makes the reducer trivially testable.

Tests

Filename suffix decides where a test runs: *.spec.ts in Node, *.svelte.spec.ts in a real browser. See testing. Don't re-test third-party libraries; test the contract between your code and them.

CLI & admin commands

Add ops commands as subcommands in src/cli/index.ts, not as one-off scripts under scripts/. The CLI runs identically in dev (tsx) and prod (bundled build/cli.mjs) — see CLI.

Don't introduce

  • A separate JWT layer on top of better-auth sessions.
  • Auto-consuming magic-link GET endpoints. The GET-then-POST flow exists for a reason — see auth.
  • Branched HTTP responses that reveal whether an account exists.
  • Manual event.cookies.set for the session cookie — better-auth's sveltekitCookies plugin owns that.
  • tsx or pnpm in the production runtime image. Bundle to JS instead.

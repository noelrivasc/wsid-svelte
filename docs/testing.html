Testing

Two vitest projects share one config. Filename suffix decides where a test runs.

Projects

SuffixRuntimeUse for
*.spec.tsNodePure functions (engine, schemas), repository tests against an in-memory SQLite.
*.svelte.spec.tsBrowser (Playwright Chromium, via vitest-browser-svelte)Component tests with real DOM and locators.

Configured in vite.config.ts. Component-test locators are async — await expect.element(...).

Running

pnpm test           # both projects, single run
pnpm test:unit      # watch mode

First run on a fresh checkout needs pnpm exec playwright install chromium.

Storybook integration

The Storybook addon-vitest auto-runs every *.stories.svelte as a smoke test (mounts the story, asserts no render error). Stories live next to their component.

Where tests live

  • Repositories: src/lib/store/EntityRepository.spec.ts. Use the in-memory DB helper to spawn a fresh sqlite per test.
  • Engine: alongside the function under test, src/lib/engine/name.spec.ts.
  • Components: next to the component, src/lib/components/path/Name.svelte.spec.ts.
  • Test data: src/lib/test_data/ — fixtures matching the Zod schemas. Used by tests, stories, and seed scripts. Never imported by production code.

What to test

  • Engine reducer branches and the schema↔reducer contract.
  • Repository behaviours that go beyond "Kysely works" — transactions, retries, mirrored writes.
  • Component contracts: that valid props render the happy path and invalid props surface the Zod error UI. Don't re-test Zod itself.

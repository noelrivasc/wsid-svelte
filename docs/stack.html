Stack

What each tool does here, and why it earned a place in the tree.

SvelteKit (Svelte 5)

The app framework. Routes under src/routes/ are thin glue — they load via the store, run pure engine code, and render components. Server entry points (+page.server.ts, hooks.server.ts) own all IO. Built with the @sveltejs/adapter-node adapter so the prod image runs node ./build/index.js.

Vite

Dev server, HMR, and production bundler under SvelteKit. Also drives Vitest's two test projects (see testing). The CLI bundle is built separately with esbuild — see CLI.

Tailwind v4

Utility CSS via @tailwindcss/vite. Theme tokens live in src/lib/app.css using @theme; utilities like bg-ground, text-body auto-generate from them. See styling.

Zod (v4)

Single source of truth for shapes. Schemas in src/lib/schemas/; types inferred from them. Used at boundaries: form input, repository reads, action validation in the reducer pipeline. Components also validate their props at render — see TestBox.svelte for the pattern.

SQLite + Kysely + better-sqlite3

One SQLite file, accessed synchronously via better-sqlite3 (native bindings), queried through Kysely for typed builders. The connection is opened with journal_mode=WAL, foreign_keys=ON. Schema is managed via Kysely migrations — see CLI and event sourcing.

better-auth

Passwordless auth with the magic-link plugin. Shares the same SQLite file (and connection) as the rest of the app, so auth tables (user, session, account, verification) live alongside domain tables. See auth.

nodemailer

SMTP transport behind a thin wrapper in src/lib/utils/mailer.ts. Dev points at mailpit; prod at a real relay. Only used by the magic-link callback.

Storybook 10

Component development sandbox at :6006. Stories live next to components (*.stories.svelte). Storybook imports the same Tailwind app.css the app does, so theming matches. The Vitest addon runs stories as tests automatically.

Vitest

Two projects in one config: *.spec.ts runs in Node (unit / repository tests), *.svelte.spec.ts runs in a real browser via Playwright Chromium (component tests with vitest-browser-svelte). See testing.

Docker + Compose + Traefik

One docker-compose.yml with dev and prod profiles. Multi-stage Dockerfile produces a slim runtime image (node + sqlite + libstdc++). Traefik handles HTTPS via Let's Encrypt in prod. See Docker setup and deployment.

citty + esbuild

citty drives the admin CLI; esbuild bundles it into build/cli.mjs as part of pnpm build so prod doesn't need tsx or pnpm. See CLI.

pnpm

Package manager. Content-addressed store, strict dep resolution. The Docker build uses corepack in the build stages but the runtime image is plain node — no pnpm at runtime.

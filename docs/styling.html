Styling & theming

Tailwind v4 utilities, generated from @theme tokens. One CSS entry, shared between the app and Storybook.

Entry point

src/lib/app.css imports Tailwind and declares the Solarized palette via @theme. Tailwind auto-generates utilities from every --color-* token.

Token families

PrefixExamplesPurpose
--color-c01 … --color-c07bg-c01, border-c03, text-c06Contrast scale, dark-mode aware. c01 = near-ground, c07 = near-body.
--color-base*bg-base02, text-base1Raw Solarized base palette. Prefer the contrast scale unless you need a specific base.
--color-accent-*bg-accent-red, text-accent-blueSolarized accents. Prefixed so Tailwind's default red-*/blue-* scales remain available.
semanticbg-ground, text-body, text-heading, bg-ctaRole-based aliases — what you reach for first.

This single file is imported by:

  • src/routes/+layout.svelte — the SvelteKit shell.
  • .storybook/preview.ts — so stories render with the same theme as the app.

Body styling

Lives inside app.css in @layer base, not in app.html. That way both contexts (SvelteKit and Storybook) pick it up via the CSS import.

Dark mode

Tokens are rewritten on :root under @media (prefers-color-scheme: dark). Utilities like bg-ground automatically flip because they reference the token.

Reach for semantic tokens first

Prefer bg-ground, text-body, text-heading, bg-cta, and the c01–c07 contrast scale over raw base or accent colors. They carry intent and flip correctly in dark mode without you having to think about it.

Flowbite components

Theme by passing Tailwind utilities via class= (using project tokens like bg-cta, bg-accent-red, border-c03, focus:ring-c01). Don't reach for Flowbite's color prop or wrap components just to retheme them.

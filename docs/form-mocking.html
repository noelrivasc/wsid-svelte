Storybook-compatible forms

How a form that posts to a SvelteKit action still renders and behaves in Storybook, where no action exists.

The problem

A SvelteKit form uses use:enhance to POST to a server action (?/addFactor). Storybook has no server, no action, and no +page.server.ts — so a real submission would 404 or hang. But we still want the form in Storybook to exercise the submit path (validation gating the button, the success flow) and to surface the submitted payload in the Actions panel. The fix is an optional mockSubmit prop that intercepts and cancels the network call when present.

Reference implementation: src/lib/components/factors/FactorForm.svelte and its wrappers. The same shape is used by the scenario forms.

The interceptor

Every form component defines its use:enhance handler as a SubmitFunction that branches on the prop. If mockSubmit is provided, hand it the form data, cancel() the request, and stop. Otherwise return the normal enhance callback that lets the real action run. 

// FactorForm.svelte
type Props = {
  action: string;
  submitLabel: string;
  initial?: Factor;
  onCancel: () => void;
  onSuccess?: () => void;
  // mockSubmit intercepts submission, cancels network call, to test actions in Storybook
  mockSubmit?: (data: Record<string, FormDataEntryValue>) => void;
};

const submit: SubmitFunction = ({ formData, cancel }) => {
  if (mockSubmit) {
    mockSubmit(Object.fromEntries(formData));
    cancel();          // no network call in Storybook
    return;
  }
  return async ({ result, update }) => {
    await update();
    if (result.type === 'success') onSuccess?.();
  };
};
<form method="POST" {action} use:enhance={submit} ...>

Key points:

  • mockSubmit is optional. Omitting it (the app) is the production path; providing it (Storybook) is the mock path. No environment sniffing.
  • cancel() aborts the actual POST, so Storybook never touches a non-existent action.
  • The signature is (data: Record<string, FormDataEntryValue>) => void — a plain object built from Object.fromEntries(formData), so the Actions panel shows readable field values.
  • The real branch returns the enhance callback and fires onSuccess only on result.type === 'success' (the action returns fail(400, ...) on a Zod miss).

Threading through wrappers

FactorForm is an implementation detail; call sites use the FactorFormAdd / FactorFormEdit wrappers, which fix the action and submitLabel and pass mockSubmit straight through. 

// FactorFormAdd.svelte
let { onCancel, onSuccess, mockSubmit }: Props = $props();

<FactorForm action="?/addFactor" submitLabel="Add" {onCancel} {onSuccess} {mockSubmit} />

Each form is its own component with a single action and a single mockSubmit. Add, edit, and delete are separate components (FactorFormAdd, FactorFormEdit, FactorFormDelete) rather than one form juggling several submit paths.

The three call sites

Context Passes mockSubmit? Result
Route (+page.svelte) no real action runs; onSuccess closes the dialog
Story (.stories.svelte) yes — fn() POST cancelled; payload logged to Actions panel
Spec (*.svelte.spec.ts) yes — a spy assert the interceptor received the expected field values 
// FactorForm.stories.svelte
import { fn } from 'storybook/test';

<Story name="FactorFormAdd">
  <FactorFormAdd mockSubmit={fn()} onCancel={fn()} />
</Story>

<Story name="FactorFormEdit">
  <FactorFormEdit factor={formSampleFactor} mockSubmit={fn()} onCancel={fn()} />
</Story>

In the route, the same wrappers are mounted without mockSubmit, so use:enhance posts to the real action and onSuccess runs the close handler.

Replicating the pattern (checklist for a new form)

  1. Add an optional mockSubmit?: (data: Record<string, FormDataEntryValue>) => void to the component's Props.
  2. Write the use:enhance handler as a SubmitFunction that branches: mockSubmit → call it, cancel(), return; otherwise return the real enhance callback.
  3. Keep one action per form component (separate add / edit / delete components), each with a single mockSubmit and its own SubmitFunction.
  4. Thread the mock prop through any wrapper component unchanged.
  5. In every story, pass the mock prop as fn() from storybook/test. Never let a story hit a real action.
  6. In routes, omit the mock prop — that is the production path.

Do not ship a form whose only submit path is a bare use:enhance POST with no mockSubmit escape hatch — it will fail or hang in Storybook and break the story-as-smoke-test in Vitest. This is the form-action exception to the "props in, callbacks out" rule in storybook: forms are allowed a real action because the mock prop keeps them portable.

Known exception: Navbar.svelte's sign-out form (#14).

Docker setup

Same compose file runs locally and in production. Two profiles: dev (mailpit on the side), implicit prod (app behind Traefik).

Profiles

Profile Services up Use
--profile dev app, mailpit Local prod-matching: image-built app + SMTP catcher for magic links.
--profile prod app, traefik What runs on the server. HTTPS via Let's Encrypt.

Local prod-matching run

pnpm dev:docker              # docker compose --profile dev up --build
pnpm dev:docker:down         # tear it down

The app container builds from Dockerfile (multi-stage: deps → build → prod-deps → runtime on node:22-alpine). ./data is bind-mounted to /app/data so the SQLite file survives container rebuilds. The entrypoint snapshots the DB, runs node /app/build/cli.mjs migrate, then starts node ./build/index.js.

Source is not bind-mounted into app. To pick up code changes, rebuild (pnpm dev:docker --build) or use the bare Vite flow.

Mailpit only (mixed flow)

If you're developing with pnpm dev but want magic links to land somewhere, start just the SMTP catcher: 

pnpm mail:docker             # mailpit on :1125 (SMTP) and :8125 (web UI)
pnpm mail:docker:down

Point the app's SMTP env vars at localhost:1125.

Admin commands against the running container

Once the stack is up, the :docker-suffixed scripts exec into app and run the bundled CLI: 

pnpm cli:docker migrate:status
pnpm migrate:docker
# Inside the container, `wsid <cmd>` is a shorter alias.

See CLI for the full command list and the dev/docker invocation matrix.

Production

The server runs the same docker-compose.yml with --profile prod. See deployment for one-time host setup, DNS, and the GitHub Actions push-to-deploy pipeline.
